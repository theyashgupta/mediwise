# Decisions

Recorded 2026-10-11 with the maintainer. Change a decision here before you change the code.

| Area | Decision | Why |
|---|---|---|
| Repo | One monorepo, Turborepo + pnpm workspaces | Old project split web and api into two repos and nothing was wired. One repo, one `pnpm check`. |
| Node | Node 24, pnpm 11 | What the machine runs. |
| Web | Vite + React 19 + TypeScript + TanStack Router + TanStack Query + Tailwind v4 + shadcn/ui | SPA is enough for an app behind login. shadcn only, no other UI kit. |
| API | Hono on Node | Small, typed, zod validation built in, `hono/client` gives the web end-to-end types with no hand-written API client. |
| Data path | Web calls the API only. Web never calls Postgres or supabase-js for data. | One authorization layer. Supabase Auth issues the JWT, the API verifies it. |
| Database | Supabase Postgres, Drizzle ORM for schema and migrations | Hosted Postgres with auth and storage in one project. Drizzle keeps schema in TypeScript. |
| Auth | Deferred to MEDI-18, after the report pipeline works. Until then the API uses a fixed `DEV_USER_ID` through one middleware. Then Supabase Auth (email + password, Google). | The maintainer's call on 2026-10-11: report quality first. Supabase Auth is free to 50k monthly users, so no Clerk. The middleware seam keeps the swap to one file. |
| Files | Supabase Storage, private bucket, signed upload and download URLs | No MinIO to run. |
| LLM | Claude via `@anthropic-ai/sdk`, structured output through a tool schema. Extraction reads the PDF text layer from `pdftotext -layout` (poppler) and sends a page as an image only when it has no text layer. Extraction and the narrative run on `claude-haiku-5-5`. Mapping of leftover names runs on `claude-sonnet-5-5`. | A report costs at most $0.06 to read (MEDI-26). Text is about a tenth of the tokens of the same page as a PDF document. Haiku extraction kept 108 of 109 mapped and score 87 on the 2024 sample. Haiku mapped "HDL/LDL" to the wrong ratio, so mapping stays on Sonnet. With a sentence-list tool schema, examples and a compact key list, Haiku passed the narrative validator on the first try 24 of 24 times at about 0.1 cent per report, against 7 of 12 and 2.8 cents for Sonnet with the old prompt (MEDI-31). Study pages (imaging reports, ECG printouts, examination forms) are copied on `claude-haiku-5-5` from a text layer and on `claude-sonnet-5-5` from a scan: Haiku read the scanned QTc 433 as 483 in 2 of 5 reads, Sonnet read all 11 ECG values right in 3 of 3, at about 0.9 cents a page (MEDI-28). Finding bodies run on `claude-haiku-5-5`: on the five dev visits, 3 runs each, Haiku passed the validator first try 11 of 15 times and dropped no finding, at about 0.06 cents a report. Sonnet passed first try 12 of 15 times, dropped one finding and cost about 1.1 cents a report (MEDI-29). |
| Scoring | Deterministic engine in `packages/engine`. The LLM never scores, never recommends. | Same report, same score. Explainable. Testable. |
| Narrative | Claude writes the plain-English narrative from the engine output only (MEDI-17). Every sentence cites a marker key, and the API rejects a sentence that cites a key not in the report. | The LLM explains, it does not judge. Nothing invented. |
| Findings | The engine picks each finding, its title, its cited keys and its rank from this visit and the previous one, so the same visits give the same findings. Claude writes only the body of each finding. A body that fails the validator twice drops its finding (MEDI-29). | The set of findings must not change between two reads. Link rules sit in the pattern catalog with a sourced `study` match, not in a second rule system. |
| Background work | In-process worker in the API that polls a `jobs` table, retries 3 times | Smallest thing that survives a restart. Move to a queue when throughput needs it. |
| Deploy | Web on Cloudflare Pages (free, commercial use allowed). API on Render free web service as one Node process in Docker. Supabase hosted (free tier). | Zero infra cost until users arrive (maintainer, 2026-10-12). The API runs the job worker in-process, so it needs a real process, not serverless functions. Render free sleeps after 15 min idle and wakes on the first request; the worker's stale-job retry covers the restart. Vercel Hobby bans commercial use and Railway has no free tier, so neither is used. |
| Payments | Cashfree Payment Gateway through the `cashfree-pg` Node SDK and the Cashfree JS checkout, behind `PAYMENTS_ENABLED` and `VITE_PAYMENTS_ENABLED` (off in production). The provider sits behind one small interface in the API payments module. Razorpay is the fallback and is not built (MEDI-33). | Lowest fee wins (maintainer, 2026-10-12). The webhook credits a pack once per payment id through a unique ledger column. |
| Landing | Next.js 16 in `apps/landing`, static export (`output: "export"`) on the Cloudflare Pages project `mediwise-landing`. Tailwind v4 with the web colour tokens. No motion library: CSS scroll-driven animations behind `@supports`, CSS transitions and IntersectionObserver. CSS inlined in the HTML. Prices and counts come from `payments.config.ts` and the engine at build time (MEDI-41). | Free hosting, like the web. Next.js 16 alone ships 134 kB of JavaScript gzipped on the first load. Motion with `LazyMotion` added about 45 kB in this build, because Turbopack and webpack both merge its lazy features into the first load, so the page broke its 150 kB budget. Without it the first load is 145 kB. The CSS is inlined in the HTML, which saves one round trip before the first paint. A number on the page cannot drift from the code. |
| Auth email | Supabase Auth sends through Resend SMTP (free plan: 3,000 a month, 100 a day, one domain) from `no-reply@mediwise.theyashgupta.me`, sender name `MediWise`. The templates live in `supabase/templates` (MEDI-44). | Supabase's own sender has a low hourly cap and a Supabase address. Resend adds no open or click tracking unless a domain turns it on, and the ticket bans tracking pixels. Brevo gives 300 a day, but turns on open tracking for transactional mail. The subdomain keeps the apex `theyashgupta.me`, which carries iCloud Mail, unchanged (maintainer, 2026-10-13). |
| Languages | English and Hindi in the web interface through a typed message tree per locale (`apps/web/src/config/messages`), a `useT` hook on `useSyncExternalStore` and `Intl.PluralRules` for plurals. No i18n library. The language is stored in `localStorage` and in Supabase `user_metadata.locale`, written with `supabase.auth.updateUser` like the password change. Catalog, engine and Claude text stay in English (MEDI-64, see `docs/i18n.md`). | No new runtime dependency and 0 kB of library code. TypeScript checks that both locales have the same keys and function parameters, which a key-string library checks only at run time. `user_metadata` keeps the choice across devices without a migration. It is an auth setting, not report data, so the data path row still holds. |
| End-to-end tests | Playwright with Chromium in `apps/e2e`, against a local Supabase (`supabase start`) with the Drizzle migrations. The API runs with `CLAUDE_STUB=true`, which answers from the golden files and never calls Claude. Tests select by `data-testid` only. CI runs the suite in the `e2e` job after `check`, with a 10-minute cap (MEDI-65). | A pull request must not break the main flow with a green CI. A stub at the Anthropic client keeps every other part of the read real and needs no key and no spend. Text selectors would break when the web text is translated. |
| Comments | Follow `.claude/rules/comments.md` | The maintainer's global rule. JSDoc only, why not what. |
| Structure | Feature modules in both apps, per `.claude/rules/structure.md`. Web: bulletproof-react style with containers. API: routes, service, repo per module. ESLint enforces the import rules. | One place for each kind of code, so every session builds the same way and `pnpm lint` catches drift. |
| Design | Tailwind tokens in one file, dark and light, shadcn components only, no custom component library | Keep the surface small. |
| Dependencies | Dependabot opens one weekly pull request for all npm minor and patch updates and one for all GitHub Actions updates. npm updates wait a 7-day cooldown. An npm major opens its own pull request with the `major` label. TypeScript 7, ESLint 10 and @types/node 26 are pinned, and Dependabot ignores their majors (MEDI-57). | typescript-eslint 8.71 supports TypeScript below 6.1 only, so TypeScript 7 fails lint with "typescript-eslint does not support TS 7.0". eslint-plugin-import 2.32 and eslint-plugin-react 7.37 support ESLint 9 at most, so ESLint 10 fails lint in `@mediwise/engine` on `import/no-default-export`. @types/node follows the Node major in the Node row (24), because Node 26 types accept APIs that Node 24 does not have. Revisit TypeScript and ESLint when those plugins add the new major to their peer range. Change @types/node together with the Node row. |
